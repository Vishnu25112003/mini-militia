# Catacombs Militia

A browser clone of a Mini Militia–style jetpack shooter on the **Catacombs** map.
React + TypeScript + Tailwind v4 + Vite, Canvas2D renderer. Single-player with bots now; online multiplayer is the next milestone.

```
npm install
npm run dev        # http://localhost:5173
npm run build
```

Controls: A/D run · W/Space jetpack · mouse aim + click fire · R reload · Q/right-click swap · G grenade (1-3 type) · E pick up · F melee · Esc pause. Touch devices get dual sticks.
Modes: Deathmatch, Team Deathmatch, Capture the Flag (bots fill the lobby).

## What the reverse engineering found (Android `com.appsomniacs.mmc` 0.14.4, arm64)

Observed in the shipped package (static analysis only):

| Area | Finding |
| --- | --- |
| Engine | **Cocos2d-x (C++)**: `lib/arm64-v8a/libcocos2dcpp.so`, plus a Java/Kotlin shell (3 dex files) for ads, billing, analytics |
| Physics | **Chipmunk** (`cpInitChipmunk`, `cpVect` in `Enemy::setBodyGravity` etc.). Box2D symbols are also linked but unused by game classes |
| Levels | Tiled `.tmx` files (`assets/sd/11catacombs_new.tmx` is Catacombs: 55×35 tiles of 64 px). Layers `tilebg` and `tile`, one object layer |
| Level objects | `sp_p_*` spawns, `wp_p_*` weapon pickups with a `weapon` pool property, `fp_*` flag points, `ctf_sp_*` CTF spawns |
| Terrain shapes | `MapShapeSquare` / `MapShapeTriangle` / `MapStaticShape` built by `MapFactory`; `MapManager::getGravityFactor` |
| Weapons | One C++ class per weapon (`Weapon` base): UZI, MAGNUM, DEAGLE, MP5, AK47, M16, M14, M93BA, TAVOR, XM8, AA12, SHOTGUN, SAWGUN, SMAW, ROCKET, MORTAR, MINIGUN, EMP, FLAMETHROWER, PHASR, RIOTSHIELD, MACHETE, grenades (FRAG, GAS, EMP, PROXY) |
| Soldier | `SoldierController` / `Local` / `Remote` / `AIController`, `SoldierView`, `Boostie` (jetpack), `HawkDrone`, `WormDrone`, `HumanoidDrone` |
| Modes | `GameManager` + `TDM`, `CTF`, `PTB` (pass the bomb), `VIP`, `COP` (co-op), Survival and Training stages |
| Networking | **RakNet** over UDP (`RakNetLAN`, `UDPProxyHandler`), `NetworkMessageDispatcher`, `ServerState`, `ClientRoom`; Google Play and LAN bridges |
| Audio | Cricket Audio bank (`da2sound16.ckb`) + `presMix.mp3` |
| Data | `mmcDatabase.sqlite` only stores the player's loadout JSON; weapon stats live in native code |

**Not recovered:** exact weapon/physics constants. They are compiled into ARM64 code and no decompiler (Ghidra/IDA/Kuna) was available for ELF on this Windows setup. Gameplay numbers in `src/game/weapons.ts` and `sim.ts` are tuned by feel; only the roster, spawn/pickup layout and level geometry come from the app.

## What came from the APK, and what did not

- **Used:** Catacombs level *geometry* (collision grid derived from tile alpha), spawn points, weapon-pickup spots and their item pools, flag stations. Generated by `scripts/build-map.mjs <extracted-apk-dir>` into `src/game/maps/catacombs.json` (numbers only).
- **Not used:** sprites, tilesets, fonts, music or sound effects. All art is drawn procedurally (`src/game/art.ts`, `renderer.ts`) and all audio is synthesised (Web Audio), so the project contains none of the original game's assets.
- **Measured, not copied:** the palette (warm khaki stone, sand highlights, near-black outlines, desert sky), weapon size proportions, and the soldier-to-tile scale come from numbers read off the original files.
- **Soldier size is set by the map:** the narrowest Catacombs tunnels are exactly 56 px tall, so the hitbox is 22×52 (4 px of slack, because a 56 px body wedges in them). Anything taller cannot reach 4 of the 10 spawns.

## Layout

```
src/game/sim.ts       deterministic fixed-step simulation (no DOM): physics, weapons, CTF, match rules
src/game/ai.ts nav.ts bots with A* navigation over a nav grid
src/game/renderer.ts  canvas drawing, particles, camera, minimap
src/game/Game.ts      loop, input, HUD snapshots
src/components/       menu, HUD, touch controls (React + Tailwind)
scripts/              build-map.mjs (APK -> map JSON), sim-test.ts (headless bot matches)
```

## Online multiplayer

```
npm run build && npm run server     # serves the game AND the websocket on http://<your-ip>:8787
# or, for development, two terminals:
npm run server                      # game server on :8787
npm run dev                         # client on :5173 (connects to ws://<host>:8787)
```

Click **Play with friends**, create a room, and send the link (`...?room=ABCD`) to friends on the same network. Up to 10 players per room; bots fill empty seats and give up their seat when a human joins mid-match.

- **Server** (`server/index.ts`): authoritative. Runs the same `sim.ts` as the offline game at 60 Hz, queues one input per player per tick behind a small jitter buffer, and broadcasts a JSON snapshot at 20 Hz (about 2 KB per snapshot with 4 soldiers, roughly 40 KB/s per client, not yet optimised).
- **Client** (`src/net/client.ts`): sends inputs with sequence numbers and predicts its own movement using the shared `applyMovement`. Each snapshot resets to the server state and replays unacknowledged inputs, with a short smoothing decay for corrections. Remote players, projectiles and effects are interpolated about 100 ms behind.
- **Protocol** (`src/net/protocol.ts`): versioned, shared by both sides. The server validates and rate-limits everything a client sends.
- **Tests**: `scripts/net-test.ts` drives a running server end to end (rooms, join, late join, junk input, disconnects, prediction error). See the header comment for how to run it.

Known limits: no lag compensation for hit detection, so shots are judged against the server's current positions. Recoil, knockback and hits are not predicted and show up as small corrections. The server is plain `ws://` with no accounts or TLS. Reaching friends outside your network needs a port-forward or a tunnel, plus `wss://` if the page is served over HTTPS.
