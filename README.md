# Mini Militia — WAN Friends Play (v1)

Own 2D jetpack shooter in the browser, playing like Mini Militia Classic, for up to 8 friends over the internet. See `MM Docs/00 Index.md` for the full plan.

## Monorepo layout

```
client/   React (menus) + Phaser (match) — Vite + TypeScript
server/   Colyseus game server — Node.js + TypeScript
shared/   Movement/collision rules, stats, map JSON — used by both client and server
```

## Prerequisites

- Node.js LTS (18+)
- npm 10+

## Install

From the repo root:

```bash
npm install
```

This installs all three workspaces (`client`, `server`, `shared`) in one pass.

## Run locally

Build the shared package first (client and server both depend on its compiled output):

```bash
npm run build:shared
```

Then start both the server and the client in watch mode:

```bash
npm run dev
```

- Server runs on `ws://localhost:2567` (health check at `http://localhost:2567/health`)
- Client runs on `http://localhost:5173` (Vite's default port)

Open the client URL in a browser — enter a name and hit **Join Test Room** (the real lobby is Phase 05; for now everyone lands in the same one `match_room`). The server is authoritative: it runs the real simulation, and the browser predicts your own movement instantly while smoothing everyone else's.

- **PC:** A/D move, W or Space fly, S crouch, mouse aim, left click fire (no gun wired up yet), V/G/R/E log their press to the console (melee/grenade/reload/pickup — wired up in Phases 07-10), right click cycles zoom, **M** toggles spawn/pickup debug markers.
- **Touch:** left joystick moves/flies/crouches, right joystick aims (holding = fire), buttons log their press the same as PC, top-left button cycles zoom.
- A dev-only panel (top-right, only in `npm run dev`) lets you change gravity/boost for the **offline sandbox** (see below) live, and dial in artificial lag/packet-loss for the **networked match** to test bad mobile networks locally.
- Open the client URL in two tabs (or two devices) to see multiplayer sync for real — the small text in the corner shows ping, tick rate, and your own prediction's drift from server truth.

### Offline movement sandbox

There's also a pure offline mode (no server, no network) left over from Phase 03, useful for quickly feeling out movement-tuning changes without needing the server running: swap `MatchScene` for `SandboxScene` in `client/src/game/GameCanvas.tsx` and `App.tsx` temporarily (it takes no `sceneData`). It's not wired into the normal app flow since Phase 04 made the networked match the primary experience.

If you change `shared/src`, re-run `npm run build:shared` (or `npm run dev --workspace=shared` in a separate terminal to rebuild on save) so the compiled `dist/` output client and server import stays current.

## The map

`shared/maps/catacombs.json` is a real Tiled JSON (`.tmj`-format) map — it's generated by code (`shared/maps/generate.ts`) rather than hand-drawn in the Tiled GUI, since no GUI was available while building this. The generator is deterministic (no randomness) and produces the octagon boundary, top/bottom cave tunnels, cross-corridor lattice, and central block described in the flow doc, with full mirror symmetry.

```bash
npm run generate-map --workspace=shared   # rebuilds catacombs.json, tileset.png, and a debug-preview.png
npm run validate-map --workspace=shared   # checks spawn/pickup counts, spacing, closed boundary, reachability
```

`validate-map` also runs automatically before `npm run build --workspace=shared`. Because the output is standard Tiled JSON, it can be opened directly in the real Tiled editor if you want to hand-tune it later — just don't re-run `generate-map` afterward, since that overwrites the file from the script's rules rather than merging your edits.

## Environment variables

| App | File | Variable | Purpose |
|---|---|---|---|
| client | `client/.env` (copy from `client/.env.example`) | `VITE_SERVER_URL` | WebSocket URL of the Colyseus server. Defaults to `ws://localhost:2567` if unset. |
| server | `server/.env` (copy from `server/.env.example`) | `PORT` | Port the Colyseus/Express server listens on. Defaults to `2567`. |

## Deployment (Phase 00 target)

- **Client → Vercel:** set project root to `client/`, set `VITE_SERVER_URL` to the server's `wss://` address.
- **Server → VPS:** clone repo, `npm install`, `npm run build`, run `server/dist/index.js` with `pm2`, behind an `nginx` reverse proxy with WebSocket upgrade headers, with a Let's Encrypt SSL certificate so the server is reachable over `wss://`.
- Vercel **cannot** run the always-on Colyseus WebSocket server — it only hosts the static client.
